<objective>
Prove criterion 2's build half by demonstration rather than inspection, then delete the proof.

Purpose: `Lightbox.tsx` is a client module today only by inheritance — its sole importer, `Attachments.tsx`, declares `"use client"`, so the whole graph below it happens to be client. That is an implicit, undocumented invariant, and Phase 7 mounts the Lightbox from a new gallery parent. The roadmap is explicit that this is *proven*, not asserted: "an `npm run build` that succeeds while importing Lightbox from a module graph that does not already establish a client boundary, not by inspection alone."

Output: a temporary server-component probe route, a **failing** build that establishes the boundary was genuinely missing, `"use client"` on `Lightbox.tsx`, a **passing** build whose Route table lists the probe, then the probe deleted and a third build confirming nothing shipped.

**Why the negative control is not optional.** Research ran five probe shapes and **three of the five produce a wrong answer**. A probe in an underscore-prefixed folder (`app/__probe/`) is silently excluded from routing by App Router's private-folder convention — the build went green and the route never existed. A probe whose `import Lightbox` is unused is elided by TypeScript/SWC before boundary analysis, so `Lightbox.tsx` never enters the server graph — the build passed with no directive. And a probe that *renders* `<Lightbox />` fails unconditionally on `document.body`, even with the directive applied. Without the negative control, a green build is indistinguishable from a mis-shaped probe. That is why steps that D-14 does not name are tasks here.

**Scope discipline.**
- The probe is **import-only and must never render `<Lightbox />`.** `createPortal(…, document.body)` reads `document` during render, and Next.js prerenders client components to HTML during static export, so a rendering probe fails with `ReferenceError: document is not defined` *regardless of the fix*. If you see `Error occurred prerendering page "/probe-tmp"` instead of a compile-time client-boundary error, the probe is wrong — do not "correct" `createPortal`, do not change the mount pattern, and do not conclude the directive failed.
- `Lightbox.tsx` retains that one render-time browser-global read — `document.body` as the `createPortal` target. It is structural to the portal design, harmless under the mount-on-click invariant (`Attachments.tsx:70-80`), and out of scope for BUILD-03. Handed to Phase 7. No guard is added. Consequently criterion 2's **stated proof mechanism** (this plan's import-only probe build) is satisfied, while criterion 2's **literal wording** ("reads no browser global during render") is **not** — that is recorded here and in the SUMMARY rather than hidden. No acceptance criterion in this plan claims the literal wording is met.
- `"use client"` is added to `Lightbox.tsx` **only**. `Scrollbar.tsx` and `RichText.tsx` are deliberately left as-is; `CLAUDE.md`'s wrong claim about the client-component list is Phase 2's BUILD-08 to correct.
- The probe is never staged and never committed. It is created, used, and removed inside this plan.
</objective>
